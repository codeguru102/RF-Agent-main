Some helpful tips for writing the reward function code:
    (1) You may find it helpful to normalize to a fixed reward range like -1,1 or 0,1 by applying transformations such as exp-style shaping to the overall reward or its reward components in order to have reasonable values for the optimization procedure. This does not mean that you should force incorrect bounds, because wrong bounds might hinder the learning algorithm from achieving the optimal policy.
    (2) If you choose to transform a reward component, then introduce a temperature or scale parameter inside the reward function. Each transformed reward component should have its own clearly named parameter when appropriate.
    (3) If the task has a goal state, it may be helpful to add a bonus to the reward function if the agent achieves the goal up to some tolerance.
    (4) Make sure every input variable is used consistently with its configured meaning and units.
    (5) Make sure you do not give contradictory reward components.
    (6) Most importantly, the reward code's input variables must contain only the variables listed in the task description.
    (7) Add concise comments in the reward code documenting the expected raw range and weighted range of each reward component, and the expected range of the final combined reward.

Return a JSON object with keys "design_thought" and "reward_code".
The design_thought value must use the required five-section Markdown format: Weaknesses of Previous Reward Function, Improvements, Reward Terms, Combined Effect, and Final Reward Function.
In the design_thought Reward Terms section, include expected raw range and weighted range for every term.
